# P05: classifier and data pipeline

The profile uses `auto`: a compatible trained head, then YAMNet, then the
numpy/scipy heuristic. Loading or inference failures retire that candidate and
log the fallback. The registry and Detection/Onset contracts are unchanged.
Every runtime classifier uses `classifier.threshold`; the head artifact also
stores its calibration suggestion. The current profile applies the synthetic
head's suggested threshold, **0.34562463893143186**.

Fallbacks share that profile threshold. In particular, the YAMNet comparison
uses its separately calibrated threshold of 0.05859375; runtime fallback at the
head's higher threshold has different sensitivity. Head metrics do not transfer
to another active classifier. Check the startup log and background report.

**The committed head is trained on synthetic fixtures only.** There were no real
raw recordings in this checkout. It is a pipeline demonstration, not a validated
detector for rubble or survivors. Retrain and calibrate using the actual contact
mic, surfaces and venue noise before using its numbers in a field claim.

## Run with real recordings

Run from the repository root with Python 3.11 and `uv`. The `ml` extra contains
only ai-edge-litert, scikit-learn and joblib as direct optional dependencies.
The heuristic remains usable without them. These commands use files, not audio
devices; hardware recording remains a human task.

```sh
uv sync --extra ml
# A human must approve these public downloads before using --allow-network.
uv run --extra ml python tools/fetch_models.py --allow-network
uv run --extra ml python tools/fetch_models.py --verify-only
uv run python tools/segment.py --raw data/raw --clips data/clips
uv run --extra ml python tools/label_review.py --index data/clips/index.csv
uv run --extra ml python tools/train_head.py --index data/clips/index.csv --provenance "Describe the actual recordings and review"
uv run --extra ml python tools/eval_background.py data/raw/bg__venue__noise__01.wav --classifier auto
uv run pytest -q
uv run --extra ml pytest -q tests/test_classifiers.py
uv run --extra ml hb sim --people 2 --can-move yes --hurt no
```

Raw filenames follow `<knock|other|bg|self>__<surface>__<description>__<NN>.wav`.
All labels except `knock` are negative. Segmentation writes the prescribed six
index columns; clip paths are relative to `index.csv`, and source paths are
relative to the raw root. It flushes end-of-file detections. Re-segmenting
regenerates clips removed during review, so review after the final segmentation.

Open `reports/review_knock.html` and `reports/review_other.html` locally to listen
and inspect difficult examples. The audio links reference local clip files;
keep those files with the review pages. Pages rank low-scoring knocks first and
high-scoring negatives first. Delete bad clips manually, or mark them, download
the JSON removal list, then explicitly run:

```sh
uv run python tools/label_review.py --index data/clips/index.csv --remove-list /path/to/review_remove.json
```

The index stays intact; training counts and excludes missing clips. Each source
recording must have one label. At least three independent recordings per binary
class are needed for separate fitting, calibration and assessment groups; more
recordings are needed for a useful estimate of a 2% false-positive target.

Training prints the selected `classifier.threshold` setting. Apply that value
to the classifier section of the intended profile before evaluating deployment
behavior. The report distinguishes calibration FPR from held-out recording FPR.
If the chosen threshold is unattainable for a baseline, it reports that fact and
the baseline's profile-threshold metrics rather than hiding the baseline.

The default head uses all 521 YAMNet scores, any embedding actually exposed by
the model, and 39 DSP features. An explicitly requested `--feature-mode dsp`
produces a separately identified `head_dsp` artifact; it never fabricates YAMNet
features. Only load locally generated or otherwise trusted joblib artifacts.

The fitted StandardScaler uses a profile-controlled minimum scale of 0.01 for
the first 521 probability features. This prevents rare class activations from
being amplified by a near-zero training variance. Embedding and DSP scales are
unchanged. Scaling is fitted only on training recordings; the threshold still
comes from separate calibration recordings. The synthetic fixtures vary their
background level independently of their label over -60 to -40 dBFS.

## Synthetic measurements and limits

[Classifier comparison](classifier.md) contains the three-way table, confusion
matrices per synthetic partition, source-group audit, calibrated operating
points, data hash, and CPU timings. The 120 synthetic recordings produced 822
clips. Thirty recording groups were reserved exclusively for calibration; the
remaining 90 groups used five-fold grouped assessment. No recording crosses
fitting, calibration and test boundaries within a fold.

The head's final calibration FPR was **3/158 = 1.90%**; its held-out FPR was
**22/520 = 4.23%**, with recall **106/108 = 98.15%**. The empirical calibration
target is not a guarantee on new recordings. Synthetic partition names are
arbitrary fixture groups, not measurements on three real surfaces.

[Background evaluation](background_synthetic_background.md) used a separate
600-second generated recording containing clap, speech-like, footstep and drop
distractors, with no survivor replies. The active head produced 32 false knocks
(192/hour when extrapolated), and P03 produced zero confirmations across ten
scheduled challenges. A ten-minute synthetic observation does not establish a
zero long-term rate. Real contact recordings, long venue background, and Pi 5
CPU latency remain unverified; macOS latency does not establish the ≤30 ms Pi
budget.

The actual head also completed the default seeded P03 survivor simulator:
confirmation at 23.33 stream seconds, followed by the answers **2 people, can
move, not hurt**. The run completed at 54.24 seconds. A regression test checks
this integration when the local head, model and optional dependencies exist;
it does not establish performance across real survivors or arbitrary fixtures.

## Periodic-event stress finding: P03 follow-up

Injecting an already-accepted knock every **1.5 seconds** at t=1.5 through 298.5
into the real DialogEngine produced **five confirmations in 300 seconds** with
the current profile and voice durations. This bypasses the acoustic classifier
and is **not a measured WAV or venue false-alarm rate**. It demonstrates that a
correlated periodic event stream can satisfy the count-based dialog under this
schedule. The evaluation starts a challenge at t=0 with the configured prior,
and resets a confirmed trial at the next scheduled challenge; the reset also
resets its background estimate. Both choices are disclosed in the background
report. The current synthetic WAV result must not be used to claim all noise
is rejected.

The evaluator preserves this adverse result. P03 engine changes are outside
P05's ownership. A P03 follow-up should assess initialization of the background
rate and behavior under periodic/correlated disturbances. Reproduce without
audio hardware or model inference:

```sh
uv run python - <<'PY'
import numpy as np
from heartbeat.classify import Detection
from heartbeat.config import load_profile
from tools.eval_background import simulate_dialog_events
events = [Detection(t=float(t), peak=0.8, snr_db=20, gated=False,
                    clip=np.empty(0, dtype=np.float32), score=1.0,
                    is_knock=True, classifier="periodic_stress", top=[])
          for t in np.arange(1.5, 300.0, 1.5)]
print(simulate_dialog_events(events, 300.0, load_profile()))
PY
```

The measured confirmation times were 37.5260625, 97.5260625, 157.5260625,
217.5260625 and 277.5260625 seconds. The current `copy_knocks` voice duration is
4.3260625 seconds. Changing P03 settings or voice durations changes this fixture.

## Reproduce the synthetic pipeline

The following recipe reproduces the source recordings using the profile's
`classifier.training.synthetic` settings and training seed. Generated WAVs and
review pages were kept under `/tmp/heartbeat-p05-data`, outside committed source.
The review pages are local working artifacts; regenerate them if `/tmp` is
removed. Tests independently synthesize their fixtures and never need these
files, the network, or hardware.

```sh
uv run python - <<'PY'
from pathlib import Path
import numpy as np
import soundfile as sf
from heartbeat import synth
from heartbeat.config import load_profile
cfg = load_profile()
s = cfg.classifier.training['synthetic']
root = Path('/tmp/heartbeat-p05-data/raw')
root.mkdir(parents=True, exist_ok=True)
rng = np.random.default_rng(cfg.classifier.training['random_seed'])
for kind in s['kinds']:
    for recording in range(s['recordings_per_kind']):
        label = 'knock' if kind == 'knock' else 'other'
        surface = f'synthetic{recording % 3}'
        events = [(s['first_event_s'] + i * s['interval_s'], kind,
                   float(rng.uniform(s['gain_min_db'], s['gain_max_db'])))
                  for i in range(s['events_per_recording'])]
        audio, _ = synth.scene(events[-1][0] + s['tail_s'], events,
                               bg_dbfs=float(rng.uniform(s['background_min_dbfs'], s['background_max_dbfs'])), seed=int(rng.integers(0, 2**31)),
                               cfg=cfg.audio.synth)
        sf.write(root / f'{label}__{surface}__{kind}__{recording:03}.wav', audio, 16000, subtype='FLOAT')
background, _ = synth.scene(s['background_duration_s'], [
    (s['first_event_s'] + i * s['interval_s'], s['kinds'][1 + i % (len(s['kinds']) - 1)],
     float(rng.uniform(s['gain_min_db'], s['gain_max_db'])))
    for i in range(int((s['background_duration_s'] - s['first_event_s']) / s['interval_s']))
], bg_dbfs=s['background_dbfs'], seed=cfg.classifier.training['random_seed'], cfg=cfg.audio.synth)
sf.write('/tmp/heartbeat-p05-data/synthetic_background.wav', background, 16000, subtype='FLOAT')
PY
uv run python tools/segment.py --raw /tmp/heartbeat-p05-data/raw --clips /tmp/heartbeat-p05-data/clips
uv run --extra ml python tools/train_head.py --index /tmp/heartbeat-p05-data/clips/index.csv --provenance "SYNTHETIC ONLY: heartbeat.synth, 120 generated source recordings with varied background levels; no real contact audio or venue data"
uv run --extra ml python tools/label_review.py --index /tmp/heartbeat-p05-data/clips/index.csv --output /tmp/heartbeat-p05-data/review
uv run --extra ml python tools/eval_background.py /tmp/heartbeat-p05-data/synthetic_background.wav --classifier auto --synthetic
```
